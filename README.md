AstrBot 做唤醒检测时，会把唤醒词和 @机器人 从消息里剥掉，模型收到的就成了半句。这个插件把剥掉的那部分补回去，另外让「名字出现在句子中间」也算叫她。

## 问题现象

唤醒检测剥掉的常常正是主语。下面拿 `小助手` 当唤醒词举例，你配的是哪个名字都一样。

| 你发送的内容 | 装之前模型收到 | 装之后模型收到 |
| --- | --- | --- |
| 小助手是谁 | 是谁 | 小助手是谁 |
| 小助手喜欢吃什么 | 喜欢吃什么 | 小助手喜欢吃什么 |
| 小助手~ | ~ | 小助手~ |
| 成员A @小助手 分组名单 | 成员A 分组名单 | 成员A 小助手 分组名单 |
| @小助手 帮我写首诗 | 帮我写首诗 | 小助手 帮我写首诗 |

前三行是主语没了，模型不知道在问谁、也不知道是谁喜欢吃什么。第四行是多人名单里自己那一份没了，机器人会以为自己没被分到组。最后一行是 @ 变成了名字。

## 插件做什么

唤醒词由 AstrBot 检测，插件不插手那一步，只管补。它挂 `on_llm_request`，在请求发出之前读一遍原始消息链，把完整文本重拼出来。

- 你打过的唤醒词原样补回，用哪个别名都认，插件这边不用再写一遍
- `@机器人` 换成平台在 At 段里带的名字，也就是这个群当时怎么称呼它。群里改了名片，补上的名字跟着变
- 别人的 @ 写成 `@昵称(qq)`，和 AstrBot 自己的写法一致，模型能看出名单里谁是谁。多重 @ 的消息里，自己那一份也会补上名字
- 钩子优先级最高，补发生在别的插件之前，记忆召回、语气判断读到的都是补全后的文本
- 只在提示词确实残缺时才动它，多轮对话和工具调用不会被误伤
- 支持按群排除、私聊关闭

### 任意唤醒词（v1.3.0）

AstrBot 面板的「配置文件」里，每个 bot 有一串唤醒词，插件直接读那串（`auto_wake_word`）：

```
甲名, 甲酱, 甲甲, 甲甲·乙
```

| 场景 | 结果 |
| --- | --- |
| 打 `甲酱 帮我看下` | 补成 `甲酱 帮我看下`，任意别名都认 |
| 打 `甲甲·乙 在吗` | 补成 `甲甲·乙 在吗`，按最长匹配 |
| 打 `甲名~` | 补成 `甲名~` |
| 打了唤醒词又 @机器人 | 只留一份，不会出现两遍名字 |

读的是消息所属的那份配置文件，所以一台机器挂多个 bot，各自读各自的，不用再拿 `bot_name_by_self_id` 一个个账号去填。

### 名字出现在句子中间也算叫她（v1.5.0）

AstrBot 只认开头的唤醒词和 @。她叫小助手时，`小助手在吗` 能叫醒，`今天好累，我要小助手陪我聊一会儿` 不能。打开 `wake_on_name`（默认开）之后，任何一条消息里出现她的名字都算叫她。

| 消息 | 会叫醒吗 |
| --- | --- |
| `小助手在吗` | 会 |
| `今天好累，我要小助手陪我聊一会儿` | 会 |
| `话说小助手刚才那个真的笑死` | 会 |
| `今天天气不错` | 不会 |

名字不用你填，插件自己去 AstrBot 里找。下面这些都算：

- 该会话配置档案里的唤醒词（`wake_prefix`）
- 插件配置里的 `extra_wake_words`
- `bot_name_by_self_id` 里属于这个 bot 账号的名字
- 平台实例名，也就是 `umi` 第一段，比如 `绫地宁宁`
- 插件配置里的 `bot_name`

命中时日志里留一行，排查「为什么没反应」时先看它：

```
[full_prompt] 唤醒命中 '小助手'（bot=10001 gid=123456789）
```

#### 只想让某一个词叫醒她（v1.5.8）

名字来源多了也有副作用。实例名如果叫 `default`、`salt` 这类通用词，任何一句带这个词的闲聊都会把她叫醒。三个开关可以收紧，缺一个都会留下口子：

```json
"wake_on_name": true,
"wake_on_instance_name": false,
"wake_on_bot_name": false
```

改完的效果是实例名和 `bot_name` 都不再参与唤醒，只有 `wake_prefix` 里写的词算数；`wake_on_name` 保持开着，所以词出现在句子中间照样唤醒。想连句中都不认、必须放句首，再把 `wake_on_name` 关掉。

`bot_name` 关掉之后仍然用于称呼，也就是被 @ 时的显示名，只是不再当唤醒词。`wake_name_min_len`（默认 2）控制名字的最短长度，比它短的不参与唤醒，单字名字默认就被跳过了。

#### 更精细的写法（可选，一般用不到）

`wake_patterns`，每行一条正则，只在她被请求时才醒：

```
要{name}
{name}[，,].*吗
```

`{name}` 会换成这个 bot 自己的名字，所以一条规则通用于所有 bot，发给别人用也不用改。

`wake_patterns_map` 可以按 bot 单独指定，每行 `平台id,正则`：

```
10001,要{name}
10002,找{name}
```

写了的 bot 只用自己这几条，没写的继续用全局。同一个 bot 可以写多行。

写错的正则只跳过那一条，日志里留一行 warn。`exclude_groups` 里排除的群以上两种都不触发。

### @机器人 的名字不用指定（v1.4.0）

@ 机器人时优先用平台在 At 里带的名字，取不到再退到昵称。这个群怎么称呼它，就补什么，不用配置。

平台没给名字时，才按下面的顺序兜底：

```
按群 bot_name_map > 按Bot bot_name_by_self_id
> 该会话配置档案里第一个像名字的唤醒词 > bot_name > 默认为「小助手」
```

「像名字」指含字母、数字或汉字，`/` 这类纯符号不算。

你自己打出来的唤醒词永远原样保留，本来就在原始消息链里，不走上面的优先级。

## 安装

1. 将本目录放入 AstrBot 的 `data/plugins/` 下
2. 在 WebUI 插件管理页面刷新并启用插件

## 配置

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `auto_wake_word` | bool | `true` | 自动读 AstrBot 里该会话配置的那串唤醒词（推荐开着） |
| `bot_name` | string | `小助手` | 最后兜底，平台没给 @ 名字、该会话也没配唤醒词时用 |
| `extra_wake_words` | list | 空 | AstrBot 里没配、但插件也想认的唤醒词，一般留空 |
| `wake_on_name` | bool | `true` | 名字出现在消息任意位置就算叫她；关掉后只认 AstrBot 的前缀和 @ |
| `wake_on_instance_name` | bool | `true` | 平台实例名（如 `绫地宁宁`）也当一个名字用 |
| `wake_on_bot_name` | bool | `true` | `bot_name`（如 `宁宁`）也当一个名字用；关掉后它只用于称呼 |
| `wake_name_min_len` | int | `2` | 名字短于这个长度不参与唤醒 |
| `wake_patterns` | list | 空 | 每行一条正则，命中才算被叫到 |
| `wake_patterns_map` | list | 空 | 按 bot 指定正则，填 `平台id,正则` |
| `bot_name_map` | list | 空 | 可选兜底，按群指定 @机器人 的名字，填 `群号,昵称` |
| `bot_name_by_self_id` | list | 空 | 可选兜底，按 Bot 账号指定名字，填 `QQ号,昵称` |
| `keep_at_marker` | bool | `false` | 开着就不换名字，保留原始的 `[At:qq]` 标记 |
| `skip_at_leading` | bool | `false` | 消息第一个组件是 @ 时不补全，给会和补全打架的部署用 |
| `exclude_groups` | list | 空 | 这些群不补全 |
| `enable_private` | bool | `true` | 私聊补不补 |

## 常见问题

**一个唤醒词把所有 bot 都叫醒**　不是插件的问题。AstrBot 按「平台实例名」决定用哪份配置档案，几个 bot 绑了同一份档案（或者都没绑，一起落到 default 上），就共用同一串唤醒词。去面板给每个 bot 的 `平台实例名:*:*` 绑各自的档案，档案里写各自的唤醒词。

**喊了个通用词，好几个 bot 同时醒**　实例名叫 `default` 时，任何一句含这个词的话都会命中。把 `wake_on_instance_name` 关掉，再确认 `wake_prefix` 里写的是真名字。

**她完全不理人，日志里也没有唤醒命中**　先看唤醒词有没有配对。唤醒词是前缀匹配，`宁宁` 认 `宁宁在吗`，不认 `绫地宁宁在吗`，因为后者开头是「绫」。要么把更长的名字也写进 `wake_prefix`，要么打开 `wake_on_name`。

**补全没发生**　多数是钩子没跑到，先看日志有没有 `[full_prompt]` 前缀的行。另外插件只在提示词确实残缺时才动它，本来就完整的话它什么也不做。

## 兼容性

只测过 aiocqhttp。AstrBot 需要 `>=v4.12.0`，因为读配置文件用了 `context.get_config(umo)`；老版本取不到会退回原来的行为。
